AutoAudit.ai Updated SaaS Documentation
Last updated: 2026-05-20

============================================================
1. PRODUCT SUMMARY
============================================================

AutoAudit.ai is a SaaS spend auditing platform for founders, finance teams,
operations teams, and lean software operators.

The product helps a company:

- Build a clear SaaS vendor inventory.
- Track software spend, seat usage, owners, renewal dates, and risk.
- Detect wasted spend before contracts renew.
- Identify zombie subscriptions, unused seats, duplicate tools, and renewal risk.
- Generate CFO-ready reports from vendor evidence.
- Draft vendor cancellation, renegotiation, and seat-reduction emails with AI.
- Keep all vendor actions human-reviewed.
- Create persistent action items from waste findings.
- Send weekly renewal digest emails to workspace owners.
- Export reports and renewal calendars.
- Prepare for paid subscription activation through Stripe Checkout.
- Measure activation, checkout, and retention through server-side analytics.

The current product is an MVP/early-access SaaS with a real frontend, protected
dashboard, Express API, MongoDB data models, JWT authentication, role-based
permissions, audit logs, activity logs, OpenAI-assisted workflows, Resend-backed
email workflows, Stripe-ready billing, and internal activation analytics.

The core trust promise is:

AutoAudit.ai does not silently contact vendors, cancel subscriptions, approve
purchases, or make financial decisions. It organizes evidence, shows why a tool
was flagged, drafts helpful text, and leaves the final action to humans.

2. TARGET USERS
============================================================

Primary users:

- Startup founders
- Finance teams
- Operations teams
- IT managers
- Procurement owners
- SaaS operations leads

Best-fit companies:

- Teams with growing software spend.
- Companies that manage renewals manually in spreadsheets.
- Teams that do not yet need a heavy procurement platform.
- Companies that want quick visibility into unused subscriptions.
- Startups that need board/CFO-ready savings summaries.

Common user pain points:

- Forgotten SaaS subscriptions.
- Renewal dates missed until it is too late.
- Paid seats that are not being used.
- Duplicate tools bought by different teams.
- Vendor ownership unclear after team changes.
- SaaS decisions spread across spreadsheets, inboxes, and memory.
- Finance needs a clean savings report but raw vendor data is messy.


============================================================
3. CORE VALUE PROPOSITION
============================================================

AutoAudit.ai turns scattered SaaS spend data into a practical review workflow.

Before AutoAudit:

- Vendors are tracked manually.
- Renewal dates are easy to miss.
- Owners are unclear.
- Seat waste is hard to calculate.
- Finance reports take manual work.
- Vendor emails are written from scratch.

With AutoAudit:

- Vendors are organized in one workspace.
- Waste signals are calculated automatically.
- Every recommendation can show "why flagged" evidence.
- Renewal exposure is visible before auto-renewal.
- Reports and emails are generated from real audit data.
- Users can export reports for finance review.
- Paid activation can be connected through Stripe.

  - Multiple vendors share the same category.
  - Highest-spend tool is treated as primary.
  - Other tools are estimated as duplicate overlap.

  - Renewal dates within 60 days are surfaced.
  - Renewals within 30 days are treated as higher risk.

- Email verification flow.
- Password reset flow with hashed reset token.
- Masked email delivery logs.
- Owner-only internal email log diagnostics endpoint.
- Email deliverability setup guide for SPF, DKIM, DMARC, and Resend domain
  verification.

Google sign-in behavior:

- Login and signup pages show "Continue with Google".
- The frontend redirects users to /api/auth/google on the API.
- The API sends users to Google with openid, email, and profile scopes.
- Google redirects back to /api/auth/google/callback on the API.
- The API verifies the Google response, creates or finds the AutoAudit user,
  signs the normal AutoAudit JWT, and redirects the browser to /oauth/google
  on the frontend.
- The /oauth/google React route saves the AutoAudit JWT, loads /api/profile/me,
  and redirects to /dashboard or the original return path.
- Existing password users can be linked to Google by matching email.
- New Google users get a company workspace automatically. Business Google
  accounts use the hosted domain when available; personal Gmail accounts get
  a personal workspace name.

OAuth redirect rules:

- Local Google callback:
  http://127.0.0.1:5000/api/auth/google/callback

- Production Google callback:
  https://autoaudit-io.onrender.com/api/auth/google/callback

- Production frontend app URL:
  https://auto-audit-io.vercel.app

- The Google Cloud OAuth client should include both local and production
  callback URLs if both environments are used.

Google OAuth client setup:

- Google Cloud Console must use an OAuth client of type "Web application".
- Authorized redirect URIs should include:
  - http://127.0.0.1:5000/api/auth/google/callback
  - https://autoaudit-io.onrender.com/api/auth/google/callback

  OAuth client where those redirect URIs are saved.

- NODE_ENV=development
- PORT=5000
- MONGODB_URI=<local or Atlas MongoDB URI>
- JWT_SECRET=<long local secret>
- JWT_EXPIRES_IN=7d
- OPENAI_API_KEY=<OpenAI API key>
- OPENAI_MODEL=gpt-5.4-mini
- CORS_ORIGIN=http://127.0.0.1:5173,http://localhost:5173
- GOOGLE_CLIENT_ID=<Google OAuth client ID>
- GOOGLE_CLIENT_SECRET=<Google OAuth client secret>
- GOOGLE_OAUTH_REDIRECT_URL=http://127.0.0.1:5000/api/auth/google/callback
- VITE_API_URL=http://127.0.0.1:5000
- VITE_SITE_URL=http://localhost:5173
- APP_URL=http://localhost:5173

Local development notes:

- Run the API with npm run dev:api.
- Run the frontend with npm run dev.
- Use http://localhost:5173/login for local browser testing.
- The API callback may stay on 127.0.0.1:5000 while APP_URL points to
  localhost:5173. This matches the current local setup.

Render backend environment:

- NODE_ENV=production
- MONGODB_URI=<production MongoDB URI>
- JWT_SECRET=<strong production secret>
- JWT_EXPIRES_IN=7d
- OPENAI_API_KEY=<OpenAI API key>
- OPENAI_MODEL=gpt-5.4-mini
- CORS_ORIGIN=https://auto-audit-io.vercel.app

- GOOGLE_CLIENT_SECRET=<Google OAuth client secret>

Vercel frontend environment:

- VITE_API_URL=https://autoaudit-io.onrender.com
- VITE_SITE_URL=https://auto-audit-io.vercel.app
- VITE_SENTRY_DSN=<frontend Sentry DSN, if enabled>
- VITE_SENTRY_ENVIRONMENT=production
- VITE_SENTRY_TRACES_SAMPLE_RATE=0.1

Important deployment details:

- Do not put GOOGLE_CLIENT_SECRET in Vercel frontend variables.
- VITE_API_URL should not end with a slash.
- src/api/client.ts also trims one trailing slash to avoid //api URLs.
- vercel.json rewrites all frontend routes to /index.html so React Router can
  handle /oauth/google, /dashboard, and other deep links.
- The canonical production frontend is:
  https://auto-audit-io.vercel.app
- Vercel preview URLs may exist, but Render APP_URL and CORS_ORIGIN should point
  to the canonical production frontend unless intentionally testing previews.

Common OAuth troubleshooting:

- Error 400 redirect_uri_mismatch means Google Cloud Console does not have the
  exact callback URL being sent by the API.
- 127.0.0.1 refused to connect after Google sign-in usually means APP_URL points
  to a local frontend that is not running or to the wrong local host alias.
- Vercel 404 on /oauth/google means the Vercel rewrite config is missing from
  the deployed commit or the Vercel project root is misconfigured.
- A spinner on "Finishing Google sign-in" means the frontend callback loaded but
  could not finish profile loading or navigation; check browser console and API
  profile requests.
